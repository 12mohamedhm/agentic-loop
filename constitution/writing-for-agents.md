# Writing for agents (house doctrine)

Adapted from Matt Pocock's writing-for-agents (MIT), rewritten in this
system's vocabulary. Governs every prose file here: disciplines, schemas'
guidance comments, SKILL.md.

**Pointers.** A pointer names out-of-context material and the condition for
reaching it. Wording decides whether it fires: front-load the trigger word,
one trigger per genuinely distinct branch, cut identity the body carries.
A must-reach target behind weak wording is a variance bug — sharpen before
inlining.

**Two loads.** Always-loaded lines cost the agent's window every turn;
un-pointered material costs the human's memory. Spend context load only on
what every run needs; spend human load only where human judgment matters.

**Hierarchy.** Steps inline and ordered; reference on demand; bulky or
branch-specific reference disclosed behind a pointer. Inline what every
branch needs; disclose what only some branches reach. Group a concept's
definition, rules, and caveats under one heading.

**Completion criteria.** End every step on a checkable, demanding bound.
"Frontier empty" beats "understanding reached"; "every modified file
accounted for" beats "produce a list". Clarity resists premature
completion; demand drives legwork.

**Leading words.** Prefer one pretrained token over a spelled-out triad:
tight, red, seam, bank, frontier, write-set. Repeat the token, never the
sentence. Industry terms over novel names.

**Positive phrasing.** State the target behavior; a prohibition earns its
place only as a hard guardrail, paired with the positive target.

**Pruning.** One meaning, one home. The environment is a source of truth;
restating it is a cache that goes stale — cache only the unwritten
convention, the reason, the gotcha. Hunt no-ops sentence by sentence; when
one fails the does-it-change-behavior test, delete the sentence. Unpruned
documents sediment.
